AI Change Checker

AI coding agents can write cloud infrastructure in seconds. Before any change reaches Azure, it is checked against the platform's rules. This page runs the real policies from the repository, compiled to WebAssembly, right in your browser.

  1. 1Agent or engineer opens a pull request
  2. 2Pipeline creates a Terraform plan
  3. 3Checker reviews the plan (this page)
  4. 4A platform engineer approves
  5. 5Pipeline applies exactly what was approved

    The rules

    RuleApplies toWhy
    Owner, cost-center and data-region tagsEveryoneCost per team and customer; residency reporting
    Azure region must match the customer's data regionEveryoneEU customer data never lands in a US region
    Storage is private, keyless, TLS 1.2EveryoneScan data is customer data, sometimes court evidence
    Build agents run on Spot VMs and scale to zeroEveryoneBuild capacity costs nothing when idle
    Geo-redundant storage needs a stated reason (warning)EveryoneIt doubles the storage bill
    No Owner, Contributor or access-admin grantsAI agentsAn agent must not widen anyone's access
    No deleting or replacing stateful resourcesAI agentsA rename that forces a replace destroys data
    No changes to Azure Policy or audit loggingAI agentsAgents must not switch off the guardrails
    At most 25 resources per changeAI agentsBig changes get split so a reviewer can follow them
    Deleting stateful resources needs a second approver (warning)EngineersSame risk, but a person may have a reason
